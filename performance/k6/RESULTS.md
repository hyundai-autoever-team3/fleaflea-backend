# k6 측정 기록

Windows 로컬 백엔드와 Docker PostgreSQL 16에서 측정했다. 모든 요청은 로그인한 테스트 계정으로 보냈고, 요청 사이에는 1초를 뒀다. 이미지 키는 `NULL`이다.

## 도감 목록: 인덱스 전후

대상: `GET /api/v1/members/me/collection-items?page=0&size=20`, 10 VU

| 도감 아이템 | 인덱스 | 시간 | 요청 수 | p95 | 실패율 |
| ---: | --- | ---: | ---: | ---: | ---: |
| 500건 | 적용 전 | 2분 | 1,163 | 70.01ms | 0% |
| 50,000건 | 적용 전 | 1분 | 549 | 136.96ms | 0% |
| 50,000건 | 적용 후 | 1분 | 590 | 27.15ms | 0% |

50,000건일 때 첫 페이지 조회는 전체 행을 읽고 정렬했다. `EXPLAIN (ANALYZE, BUFFERS)` 실행 시간은 약 15.43ms였다. `(member_id, created_at DESC)` 인덱스를 적용한 뒤에는 필요한 20행만 읽었고 약 0.07ms가 걸렸다. 공개 목록을 위한 `(member_id, is_public, created_at DESC)` 인덱스도 함께 추가했다. 두 인덱스는 Flyway V8에 넣었고, 서버를 다시 띄워 적용을 확인했다.

같은 50,000건 조건에서 HTTP p95는 136.96ms에서 27.15ms로 줄었다. 이 테스트는 10 VU가 매 요청 뒤 1초씩 쉬므로 최대 처리량 측정은 아니다.

## 다른 조회 API

각 API를 10 VU, 30초로 실행했다. 모두 실패율 0%였다.

| API | 데이터 | p95 |
| --- | --- | ---: |
| 회원 도감 목록 | 도감 아이템 50,000건 | 160.73ms |
| 도감 상세 | 아이템 1건 | 39.67ms |
| 플리마켓 목록 | 참여 마켓 100건 | 1,579.74ms |
| 플리마켓 상세 | 마켓 1건 | 544.05ms |
| 플리마켓 참여자 목록 | 참가자 1명 | 278.22ms |
| 도감 거래 상세 | 거래 요청 1건 | 1,318.47ms |

플리마켓 목록을 다시 측정했을 때 p95는 691.27ms였다. 해당 조회 SQL의 DB 실행 시간은 약 4.33ms였다. API 응답 지연의 원인은 이번 측정으로 특정하지 못했다.

## 도감 거래 상태 변경

3 VU, 30초 동안 서로 다른 아이템 81개로 요청을 만들었다. 생성·수락·완료·거절·취소 요청은 총 189건이며 모두 예상한 상태 코드로 끝났다. 전체 HTTP p95는 110.07ms, 실패율은 0%였다. DB에는 완료·거절·취소가 각각 29건 남았다.

이 p95는 다섯 동작을 합친 값이다. 동작별 수치가 필요하면 스크립트에 넣은 `name` 태그로 분리해 측정해야 한다. 이미지 업로드가 필요한 도감 아이템·플리마켓 생성과 수정은 측정하지 않았다.
