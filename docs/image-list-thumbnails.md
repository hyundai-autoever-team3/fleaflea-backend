# 마켓·도감 목록 이미지

## 동작

GCS 사용 시 `items/`, `collection-items/` 원본 업로드 후 선택적으로 목록용 JPEG를 만든다. 긴 변 최대 480px, 비율 유지, 확대하지 않음, JPEG 품질 0.8이며 EXIF 회전·반전을 반영한다. 투명 영역은 흰 배경으로 합성하고 애니메이션 이미지는 첫 프레임을 사용한다. 새 파일에는 원본 EXIF 위치 정보 등을 복사하지 않는다. 원본은 변경하지 않으며 상세 응답의 URL도 유지한다.

파생 키는 `thumbnails/v1/{originalKey}.jpg`다. 원본보다 작은 경우에만 저장한다. 이미지 생성 실패는 원본 업로드를 실패시키지 않는다. 복사 시 존재하는 썸네일도 복사하고 삭제·트랜잭션 롤백 정리 시 파생 파일도 삭제한다. 파생 파일 삭제 실패는 로그에 남기며 원본 삭제 성공을 취소하지 않는다. 실패한 파생 파일 정리는 별도 운영 확인이 필요하다.

목록의 기존 `imageUrl` 필드에서 썸네일을 선택한다. URL 생성 전에 페이지 내 중복·null 키를 제거하고 GCS SDK 배치 조회로 파생 파일 존재를 확인한다. 존재 여부는 인스턴스별로 최대 10,000개·1분간 보관한다. 기존 이미지에 썸네일이 없거나 존재 확인이 실패하면 원본 URL을 사용한다. S3/MinIO는 기존 원본 URL 동작을 유지한다.

기존 GCS 서명 URL Caffeine 캐시를 재사용한다. 서명 URL 캐시가 비어 있을 때의 최초 서명 비용과 API가 필요 이상으로 많은 항목을 요청하는 문제는 이 변경으로 없어지지 않는다. 앱 재시작/Blue·Green 간 캐시는 공유되지 않는다. 이번 PR은 프론트의 `size=100` 요청이나 로딩 상태 로직을 변경하지 않는다.

## 기존 이미지 백필

**운영 백필은 자동으로 실행되지 않는다.** 애플리케이션 시작이나 목록 조회 중 원본을 내려받고 변환하지 않는다. 운영 적용 전에 격리된 버킷에서 확인한 뒤 버킷과 인증 주체를 검토해 명시적으로 실행한다. Java 25와 ADC(Application Default Credentials)가 필요하며, 앱 `.env`의 비밀 값을 읽지 않는다.

먼저 읽기 전용 후보 확인:

```bash
./gradlew backfillImageThumbnails --args='--bucket=YOUR_BUCKET --limit=100'
```

실제 생성:

```bash
./gradlew backfillImageThumbnails --args='--bucket=YOUR_BUCKET --limit=100 --apply'
```

- 기본은 dry-run이다. 원본 목록과 파생 파일 존재 여부만 확인하며 내려받거나 쓰지 않는다.
- `--limit`은 새 파생 파일의 **후보 수** 제한이다. 이미 존재하는 파일은 건너뛰므로 반복 실행으로 이어갈 수 있다. 목록 스캔 수·읽기 비용 자체의 상한은 아니다.
- `items/` 다음 `collection-items/` 순서로 처리한다. 이미 있는 파일은 덮어쓰지 않는다. 원본과 DB는 변경하지 않는다.
- 원본 100MB·2천만 픽셀 제한, 순차 처리, JVM 최대 힙 512MB다. 큰 원본은 비용과 처리 시간이 발생하므로 작은 단위로 실행한다.
- 다운로드에 generation 조건을 적용하고 생성 직전 원본 generation을 재확인한다. 삭제·교체된 원본은 건너뛰며, 파생 파일도 doesNotExist 조건으로 중복 생성을 막는다.
- 생성 직전 확인 이후 원본 삭제가 경합하면 고아 파생 파일이 남을 수 있다. 가능하면 이미지 쓰기가 없는 유지보수 시간에 실행하고 실패·고아 파일을 확인한다. 파생 키만으로 접근 권한을 부여하지 않으며 원본 DB 접근 검증은 유지된다.
- 작은 원본은 JPEG보다 작아 생성하지 않을 수 있다. 이런 파일은 반복 실행 시 다시 후보가 된다. 요약의 `skipped`와 `failed`를 확인한다.
- 읽기에는 버킷 목록·객체 조회, 생성에는 파생 객체 생성 권한이 필요하다. 원본 삭제·DB 쓰기 권한은 필요하지 않다.
- 존재하지 않음 캐시는 최대 1분 후 갱신된다. 백필 직후 일부 응답이 원본인 것은 가능하다.

요약의 `originalBytes`와 `thumbnailBytes`는 실제 생성한 동일 파일 집합의 비교다. 원본 미변경, 이미지 방향·색상, 목록 200 및 상세 원본 조회를 확인한다. 이 수치는 네트워크 전체 응답 시간이나 사용자 체감 개선율을 의미하지 않는다.

## 검증 기준

- 크기·비율 유지, 작은 이미지 확대 방지, 투명 영역 배경과 EXIF 회전
- 썸네일 배치 선택, 누락·조회 실패 원본 fallback, 일시 장애 후 재시도
- 업로드·복사·삭제 및 캐시 무효화
- 백필 dry-run 무쓰기, 기존 파일 건너뛰기, generation 조건
- 마켓·도감 목록 회귀 및 기존 상세 URL 유지

운영 반영 후 브라우저에서 동일 이미지·동일 캐시 조건으로 전송량과 API/이미지 완료 시간을 다시 측정한다. 기존 사진은 백필 전까지 원본 fallback이며, 코드 배포만으로 모두 작아지지는 않는다.
